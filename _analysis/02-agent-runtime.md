## Verdict

**Agent loop — OpenClaw wins.** OpenClaw's loop is a first-class, provider-independent state machine in `B/packages/agent-core/src/agent-loop.ts` (1667 lines). It has a two-level structure — an outer follow-up loop (`while (true)`, line 287) wrapping an inner tool/steering loop (`while (hasMoreToolCalls || pendingMessages.length > 0)`, line 291) — with mid-run message injection ("steering"), per-checkpoint abort checks (`stopIfAborted()` called at six distinct points, lines 292, 331, 482, 502, 566), typed abort semantics that distinguish a deliberate yield from a user interrupt (`isTurnHandoffAbort`, `B/packages/agent-core/src/turn-interruption.ts:42`), whole-batch tool admission with a one-shot critical-tool-loop recovery budget (`ToolLoopIntervention`, `B/packages/agent-core/src/types.ts:68`), and per-tool `executionMode: "sequential" | "parallel"` (`types.ts:592`) with async tool batches. Agno's tool-call cycle is not in the agent layer at all — it lives inside the provider adapter base class, `A/models/base.py:700` (`while True:`), duplicated three times for sync/async/stream (lines 700, 924, 1415). It has no abort signal, no mid-run injection, and it exits by `break` on `requires_confirmation` / `external_execution_required` / `requires_user_input` (lines 848, 852, 856). Agno's genuinely superior pieces are **run-level retry with exponential backoff** (`A/agent/agent.py:292-297`: `retries`, `delay_between_retries`, `exponential_backoff`; applied at `A/agent/_run.py` `num_attempts = agent.retries + 1`) and a hard `tool_call_limit` (`A/agent/agent.py:183`) — OpenClaw's core has neither (only `maxRetryDelayMs`, `B/packages/agent-core/src/agent.ts:159-160`, a cap on provider-requested delays), and I found **no max-steps/max-turns bound in OpenClaw's agent loop** (grep for `maxSteps|maxTurns|max_steps` across `B/src` and `B/packages/agent-core/src` returns only unrelated ping-pong and repair-agent budgets, e.g. `B/src/infra/update-repair-agent.ts:63`).

**Reasoning — Agno wins, decisively.** Agno has a real `reasoning/` package: a `ReasoningManager` (`A/reasoning/manager.py`, 44 KB) with per-provider native-reasoning extraction modules for Anthropic, OpenAI, DeepSeek, Gemini, Groq, Ollama, VertexAI, Azure AI Foundry, Moonshot, OpenRouter; a typed chain-of-thought schema `ReasoningStep{title, action, result, reasoning, next_action, confidence}` with `NextAction ∈ {continue, validate, final_answer, reset}` (`A/reasoning/step.py:7-31`); reasoning surfaced as first-class stream events (`ReasoningStartedEvent`/`ReasoningStepEvent`/`ReasoningContentDeltaEvent`/`ReasoningCompletedEvent`, `A/run/agent.py:389-410`); and an explicit scratchpad toolkit `ReasoningTools` with `think()` and `analyze()` (`A/tools/reasoning.py:10, 50, 116` — "Use this tool as a scratchpad to reason about the question and work through it step-by-step"). Honest caveat: `ReasoningManager.reason()` **only** supports native reasoning models and errors otherwise (`A/reasoning/manager.py:94-102`) — the manual CoT path is `ReasoningTools`, not the manager. OpenClaw has **no equivalent**. Its entire `reasoning.ts` is 39 lines mapping a logical `ThinkingLevel` to a provider `reasoning` option (`B/packages/agent-core/src/reasoning.ts:10-38`), plus level re-resolution across mid-run model switches (`agent-loop.ts:459-480`). There is no reasoning-step schema, no scratchpad tool, no reflection/planning loop in the studied paths. The closest is `B/src/agents/tools/goal-tools.ts` (create/get/update a session goal with a token budget) — goal tracking, not reasoning.

**Teams — Agno wins on coordination semantics; OpenClaw wins on process infrastructure. Overall: Agno.** Agno's `A/team/` ships four explicit coordination modes as a typed enum (`A/team/mode.py:12-25`): `coordinate` (supervisor picks members, crafts tasks, synthesizes), `route` (router returns a member's response directly), `broadcast` (same task to every member; `arun` concurrent, `run` sequential), and `tasks` (leader decomposes goals into a shared task list and loops until done). The `tasks` mode is backed by a real shared work model — `Task{id, title, status ∈ {pending,in_progress,completed,failed,blocked}, assignee, parent_id, dependencies, result, notes}` and `TaskList` (`A/team/task.py:12-72`) — driven by model-facing tools `create_task` / `update_task_status` (`A/team/_task_tools.py:179, 220`) and delegation tools `delegate_task_to_member(member_id, task)` / `delegate_task_to_members(task)` (`A/team/_default_tools.py:690, 1051`). Cancellation cascades from team run to member runs (`A/run/cancel.py:119-175`, `register_member_run`, `adrain_member_tasks`). OpenClaw has no in-process team abstraction; it has **process-level fan-out**: a swarm scheduler with per-group lanes and concurrency admission (`B/src/agents/subagents/swarm/swarm-scheduler.ts`, `SwarmGroupLane{limit, active, queue}`), bounded config `{maxConcurrent: 8, maxChildrenPerGroup: 50, maxTotalPerGroup: 200, waitTimeoutSecondsMax: 600}` (`B/src/agents/subagents/swarm/swarm-config.ts:14-21`), a ~60-file subagent registry with lifecycle, recovery, leases and restart reconciliation (`B/src/agents/subagents/registry/`), spawn planning/admission/depth limits (`B/src/agents/subagents/spawn/`), a delegation capability gate (`full` vs `report_only`, `B/src/agents/delegation-capability.ts:12-27`), and ACP (Agent Client Protocol) as a standards-based agent-to-agent transport (`B/src/acp/`, `B/packages/acp-core/`). These are complementary, not competing: Agno defines *what coordination means*, OpenClaw defines *how many processes may run and who owns them*.

**Workflows — Agno wins, no contest.** Agno has a genuine deterministic orchestration engine in `A/workflow/`: `Step`, `Steps`, `Loop`, `Parallel`, `Condition`, `Router` (`A/workflow/__init__.py`), with nested workflows as step executors (`A/workflow/steps.py:24-35` `WorkflowSteps` union includes `"Workflow"`). `Loop` has `max_iterations` (default 3) and an `end_condition` that may be a callable **or a CEL expression** (`A/workflow/loop.py:76-77`, evaluated via `A/workflow/cel.py`). `Router` selects by callable or CEL over `step_choices` (`A/workflow/router.py:54-70`). `Condition` takes bool | callable | CEL (`A/workflow/condition.py:100-140`). `Parallel` uses `ThreadPoolExecutor` for sync (`A/workflow/parallel.py:390, 586`) and `asyncio.gather` for async (line 762). `Step` carries `max_retries: int = 3` and `skip_on_failure` (`A/workflow/step.py:196-198`). Pause/resume is persisted: `workflow_run_response.status = RunStatus.paused; paused_step_index; paused_step_name` then `save_paused_session(...)` (`A/workflow/workflow.py:2962-2969, 3339`). OpenClaw has **no step-graph engine**. Its `B/src/tasks/task-flow-registry.*` is a SQLite status ledger for plugin-managed flows — `TaskFlowRecord{flowId, status ∈ queued|running|waiting|blocked|succeeded|failed|cancelled|lost, goal, currentStep?: string, stateJson, waitJson, revision}` (`B/src/tasks/task-flow-registry.types.ts:10-20, 47-66`). `currentStep` is an opaque free-text label; there is no step list, no branching, no parallel/loop/router primitive. `B/src/flows/` is not workflows at all — it is channel-setup and `doctor` health-check flows.

**Session/state/context — OpenClaw wins, decisively.** OpenClaw persists a **session DAG**, not a list: `SessionTreeEntry` is a discriminated union of `message | thinking_level_change | model_change | compaction | reset | branch_summary | custom | custom_message | label | session_info | leaf`, each with `parentId` (`B/packages/agent-core/src/harness/types.ts:38-129`). Context assembly resolves a window by finding the last `reset`/`compaction` boundary and its `firstKeptEntryId`, then repairs orphaned tool-result pairs (`B/packages/agent-core/src/harness/session/session.ts:15-29, 62-80`, `tool-result-pairing.ts`). Compaction is token-budget driven and real: `DEFAULT_COMPACTION_SETTINGS = {enabled: true, reserveTokens: 16384, keepRecentTokens: 20000}` with `shouldCompact`, `findCutPoint`, `generateSummary`, `compact`, a 16 000-char summary cap, and image-block token accounting (`B/packages/agent-core/src/harness/compaction/compaction.ts:121, 173-177, 299, 310, 454, 526, 942`). Above that sits a **pluggable `ContextEngine` contract** with a full lifecycle — `bootstrap / ingest / ingestBatch / afterTurn / maintain / compact`, declared host capabilities, prompt-cache telemetry, and a runtime-provided `rewriteTranscriptEntries()` for safe branch-and-reappend rewrites (`B/src/context-engine/types.ts:50-71, 170-205, 213-290`). Agno's context management is much thinner: history is a fixed run window (`add_history_to_context` + `num_history_runs`, default 3 — `A/agent/agent.py:148-150, 562-563`), plus an optional LLM `SessionSummary` (`A/session/summary.py`). Its genuinely distinct wins are **tool-result compression** (`A/compression/manager.py` — an LLM pass that rewrites tool outputs, default triggers after 3 tool results) and **tool-result offloading** to a file store with `read_result`/`search_result` pointers (`A/offload/store.py`, `A/offload/types.py`). Note `A/context/` is *not* context-window management — it is a retrieval-provider abstraction (`ContextProvider` over fs/gmail/slack/gdrive/mcp/web/wiki, exposed as `default|agent|tools` modes — `A/context/provider.py`, `A/context/mode.py`).

**HITL — Agno wins on the state model; OpenClaw wins on the operator transport. Overall: Agno.** Agno models HITL as a *durable, resumable run pause*. `RunRequirement` carries `PauseType = "confirmation" | "user_input" | "user_feedback" | "external_execution"` with resolution predicates `needs_confirmation` / `needs_user_input` / `needs_user_feedback` (`A/run/requirement.py:10-90`); the model loop breaks on any unresolved requirement (`A/models/base.py:846-856`); the run is persisted `paused` and resumed via `continue_run`. It is declarative at the tool level — `@approval` / `@approval(type="audit")` composes with `@tool` in either order and sets `requires_confirmation` automatically (`A/approval/decorator.py:21-76`, `A/approval/types.py`). It is also declarative at the *workflow* level — `HumanReview{requires_confirmation, requires_user_input, requires_output_review, requires_iteration_review, on_reject, on_error, max_retries, timeout}` attachable to Step/Loop/Router/Condition/Steps (`A/workflow/types.py:64-105`). And Agno has input **guardrails** as pre-hooks: `BaseGuardrail.check/async_check`, `PromptInjectionGuardrail` (18 pattern rules), `PIIDetectionGuardrail`, `OpenAIModerationGuardrail` (`A/guardrails/`), executed synchronously ahead of buffered non-guardrail hooks (`A/agent/_hooks.py:76-89`). OpenClaw's strength is the *transport and classification*: a risk classifier that buckets tool calls into `readonly_scoped | readonly_search | mutating | exec_capable | control_plane | interactive | other | unknown` with an `autoApprove` flag (`B/src/acp/approval-classifier.ts:34-46`), an ACP permission relay producing `allow-once | allow-always | deny` options (`B/src/acp/permission-relay.ts:9-70`), a full approval transport with timeouts, deferred approvals and an explicitly final denial message (`B/src/agents/agent-tools.before-tool-call.approval.ts:42-56`), a blocking `ask_user` tool (`B/src/agents/tools/ask-user-tool.ts`), and run-level approval-wait accounting (`B/src/agents/agent-run-approval-wait.ts`). But OpenClaw *blocks inside the tool call*; it does not persist a resumable "paused run with an outstanding requirement". I found **no input-content guardrails** (PII / prompt-injection / moderation) anywhere in the OpenClaw paths studied — OpenClaw gates by tool policy (`B/src/agents/tool-policy.ts`, allow/deny lists) rather than by content. Guardrail coverage outside the studied paths is **UNVERIFIED**.

## Architectural incompatibilities

1. **The loop lives at different layers.** Agno's tool-call iteration is inside the *provider adapter* (`A/models/base.py:700`, and again at 924 and 1415 for async/stream). OpenClaw's is *above* the provider, and the provider is reduced to a `StreamFn` that must never throw — failures must be encoded as an `AssistantMessage` with `stopReason: "error" | "aborted"` (`B/packages/agent-core/src/types.ts:19-25`). These cannot coexist: if an Agno `Model` is plugged into `agentLoop`, its internal `while True` will run a second, invisible tool loop. **Reconciliation:** Agno `Model` subclasses must be adapted to `StreamFn` with their tool loop disabled — i.e. one call, one assistant message, tool calls returned unexecuted.

2. **"Agent" means different things.** In Agno an `Agent` is an in-process configuration object (model + tools + db + hooks) whose `run()` returns a `RunOutput`; identity is `agent_id` on a session row (`A/session/agent.py:16-45`). In OpenClaw an agent is a *durable, addressable, leased entity* with a SQLite-backed registry, workspace, provenance and lifecycle (`B/src/state/openclaw-agent-db-schema.ts`, `…-db-lease.ts`, `…-db-lifecycle.ts`, `B/src/state/agent-deletion-journal.ts`). **Reconciliation:** the merged system needs an explicit split between *AgentDefinition* (Agno's config object, serializable) and *AgentInstance/Session* (OpenClaw's leased, recoverable runtime row). Agno's `Agent` must become a definition that OpenClaw materializes.

3. **Transcript shape: list vs DAG.** `AgentSession.runs` is an ordered list of runs (`A/session/agent.py:38`); OpenClaw stores a parent-linked tree with `leaf` pointers, `branch_summary`, `compaction` and `reset` boundary entries (`B/packages/agent-core/src/harness/types.ts:38-129`). A list is a degenerate DAG, so the DAG must win — but Agno's `RunOutput` boundaries carry metrics, requirements and status that have no entry type in OpenClaw's union. **Reconciliation:** add a `run_boundary` `SessionTreeEntry` variant carrying `RunOutput` metadata; project Agno runs onto contiguous entry spans.

4. **Cancellation: registry vs signal.** Agno cancels by mutating a process-global registry keyed on `run_id` and polling `raise_if_cancelled` (`A/run/cancel.py:11, 99-106`); OpenClaw threads an `AbortSignal` into every tool `execute(toolCallId, params, signal, onUpdate)` (`B/…/types.ts:579-584`) and encodes *intent* in `signal.reason.turnHandoff` (`B/…/turn-interruption.ts:42-52`). A registry cannot express "this abort was a deliberate handoff, do not emit interruption guidance". **Reconciliation:** one `AbortController` per run, registered in a run table; `cancel_run(run_id)` becomes `controller.abort(reason)`; Agno's member-run cascade (`A/run/cancel.py:119-175`) is reimplemented as child controllers.

5. **HITL: pause-the-run vs block-the-tool.** Agno *unwinds* — the loop breaks, the run is persisted `paused` with unresolved `RunRequirement`s, and resumes later, possibly in a different process (`A/models/base.py:846-856`; `A/run/requirement.py`). OpenClaw *blocks in place* — `beforeToolCall` awaits an approval with a timeout, and denial produces an error tool result (`B/src/agents/agent-tools.before-tool-call.approval.ts:42-56`). A blocked in-process await cannot survive a restart; an unwound pause cannot hold an open exec session. **Reconciliation:** `AgentToolResult` needs a third disposition beyond ok/error — `suspend`, carrying a `RunRequirement` — so the loop can either await (interactive) or unwind and persist (durable) from the same tool contract.

6. **Reasoning is a message in A, a stream option in B.** Agno appends reasoning content as extra `Message`s into `RunMessages` before the model call and emits `ReasoningStepEvent`s; OpenClaw passes `reasoning` as a `SimpleStreamOptions` field derived from `ThinkingLevel` (`B/…/reasoning.ts:10-38`) and re-derives it on mid-run model switches (`agent-loop.ts:459-480`). **Reconciliation:** `ReasoningStep` must become a persisted transcript entry (OpenClaw already has the slot: `CustomMessage{customType, display, excludeFromContext}`, `B/…/types.ts:431-446`), and `ThinkingLevel` must be carried alongside Agno's `reasoning_model` rather than replacing it.

7. **Workflow state vs session state have separate stores.** Agno persists paused workflow state into `WorkflowSession` via its own DB layer (`A/workflow/workflow.py:2962-2969`, `A/session/workflow.py`); OpenClaw persists everything into `openclaw-agent-db` with leases and migrations. Two durable stores for one paused run is a split-brain. **Reconciliation:** workflow run state becomes rows in the OpenClaw agent DB; `save_paused_session` is reimplemented against it.

8. **Tool schema and validation differ.** Agno uses Python callables wrapped in `Function`/`Toolkit` with runtime introspection; OpenClaw uses TypeBox `TSchema` with pre-execution argument validation and a typed `errorKind: "argument-validation"` (`B/…/types.ts:561-593`, `validation.ts`). **Reconciliation:** one JSON-Schema tool descriptor as the wire type; Agno's `Function` metadata (including `requires_confirmation`, `external_execution`, `approval_type`) must be projected onto OpenClaw `AgentTool` extension fields.

9. **Event vocabularies do not align.** Agno emits ~30 run events including pre/post-hook, memory-update, session-summary and reasoning events (`A/run/agent.py:144-410`); OpenClaw emits 11 (`B/…/types.ts:612-651`) and has no notion of hook/memory/summary events. Anything consuming Agno events (its `os/` API, SSE) breaks on the smaller vocabulary. **Reconciliation:** the merged `AgentEvent` union must be a superset; OpenClaw's `message_update` carries a nested `assistantMessageEvent`, which is the right place to hang Agno's delta events.

## Salvage list

**From Agno (loser on: agent loop, session/context):**

- `A/agent/agent.py:292-297` + retry driver in `A/agent/_run.py` — run-level `retries` / `delay_between_retries` / `exponential_backoff`. OpenClaw's loop has no run-level retry at all.
- `A/agent/agent.py:183` `tool_call_limit` → `A/models/base.py:752` `function_call_limit` — a hard tool-call budget; OpenClaw's loop is unbounded in steps.
- `A/compression/manager.py` (`CompressionManager`, `DEFAULT_COMPRESSION_PROMPT`) — LLM compression of *tool results* is orthogonal to, and strictly additive over, OpenClaw's transcript compaction.
- `A/offload/store.py`, `A/offload/types.py`, `A/offload/tools.py` — oversized tool results become files with `read_result`/`search_result` pointers; OpenClaw only truncates.
- `A/session/summary.py` (`SessionSummaryManager`) — user-facing session summary, distinct from compaction summaries.
- `A/run/cancel.py:119-175` — team→member cancel cascade with bounded drain (`adrain_member_tasks`); OpenClaw's subagent cancel path has no equivalent bounded drain semantics in what was read.
- `A/context/provider.py` + `A/context/mode.py` — the `ContextProvider` retrieval abstraction with `default|agent|tools` exposure modes; OpenClaw has no equivalent façade for turning a data source into either a sub-agent or a tool set.

**From OpenClaw (loser on: reasoning, teams, workflows, HITL state model):**

## Bridge requirements

The merged runtime is: **OpenClaw's `agentLoop` executes; Agno's `Workflow`/`Team` drive it.** That means Agno's orchestrators must be able to invoke an OpenClaw run and consume its results without either side importing the other's internals. The contract below names the exact types that must cross the boundary.

**1. Run invocation (Agno → OpenClaw).** A `RunRequest` carrying:
- `AgentContext` = `{systemPrompt: string, messages: AgentMessage[], tools?: AgentTool[]}` (`B/…/types.ts:596-603`), built from Agno's `RunMessages` + resolved `Function` set.
- `AgentLoopConfig` subset: `model: Model`, `thinkingLevel: ThinkingLevel` (`B/…/types.ts:408`), `toolExecution: ToolExecutionMode` (`:35`), `convertToLlm`.
- `AbortSignal` derived from Agno's `run_id` (replaces `raise_if_cancelled`).
- New required fields with no current home: `maxToolCalls` (from `tool_call_limit`) and `retryPolicy {attempts, delayMs, exponential}` (from `A/agent/agent.py:292-297`). Both must be added to `AgentLoopConfig` — neither exists today.

**2. Tool contract (bidirectional).** `AgentTool<TParameters extends TSchema, TDetails>` (`B/…/types.ts:561-593`) is the canonical shape. Agno `Function` must project onto it, plus three new extension fields carrying Agno's HITL flags: `requiresConfirmation?: boolean`, `requiresUserInput?: boolean`, `externalExecution?: boolean`, and `approvalType?: "required" | "audit"` (from `A/approval/decorator.py:52-62`).

**3. Suspension (the load-bearing new type).** `AgentToolResult<T>` (`B/…/types.ts:540-552`) currently supports only `terminate?: boolean`. It must gain a suspend disposition carrying an Agno `RunRequirement` (`A/run/requirement.py:14`) with `PauseType ∈ {confirmation, user_input, user_feedback, external_execution}` (`:10`), plus `UserInputField[]` / `UserFeedbackQuestion[]`. `agent-loop.ts` must treat a suspending batch like `terminateRun` but persist the requirements rather than emitting a failure message. This is the single largest code change the merge requires.

**4. Approval policy front end.** `AcpApprovalClass` (`B/src/acp/approval-classifier.ts:34-41`) + `PermissionOption` (`allow-once | allow-always | deny`, `B/src/acp/permission-relay.ts:9`) must be the *producer* of a `RunRequirement` when a tool is classified `mutating | exec_capable | control_plane | interactive`, and the *consumer* of its resolution. Contract: `classify(toolCall) -> {approvalClass, autoApprove}`; if `!autoApprove`, emit `RunRequirement`; resolution sets `confirmation: boolean` + `confirmation_note`.

**5. Event bridge (OpenClaw → Agno).** `AgentEvent` (`B/…/types.ts:612-651`, 11 variants) must map onto `RunOutputEvent`/`RunEvent` (`A/run/agent.py:144`). Required mappings: `agent_start→RunStartedEvent`, `message_update→RunContentEvent`, `tool_execution_start/end→ToolCallStartedEvent/ToolCallCompletedEvent`, `agent_end→RunCompletedEvent`, aborted `turn_end→RunCancelledEvent`, suspend→`RunPausedEvent`. Agno's reasoning/memory/hook events have no OpenClaw source and must be emitted by the merged runtime directly.

**6. Transcript bridge.** Agno `Message` ↔ OpenClaw `AgentMessage` (`B/…/types.ts:492`, a union including `CustomMessage`, `BashExecutionMessage`, `CompactionSummaryMessage`, `BranchSummaryMessage`). Agno's `RunOutput` becomes a new `run_boundary` variant of `SessionTreeEntry` (`B/…/harness/types.ts:118-129`). `ReasoningStep` (`A/reasoning/step.py:14`) crosses as `CustomMessage{customType: "agno:reasoning-step", display: true, excludeFromContext: true}`.

**7. Context bridge.** Agno's message assembly must be replaced by a `ContextEngine.assemble` call returning `AssembleResult{messages, estimatedTokens, systemPromptAddition?, contextProjection?}` (`B/src/context-engine/types.ts:7-39`); Agno's `RunMessages` is constructed *from* that result, never independently. Compaction is requested through `ContextEngine.compact` returning `CompactResult` (`:112-136`); Agno's `CompressionManager` runs as a pre-assemble tool-result transform, before, not instead of, compaction.

**8. Workflow ↔ run boundary.** `StepInput` / `StepOutput` (`A/workflow/types.py:300, 538`) are the only types a workflow step exchanges with a run. A step whose executor is an agent must produce a `RunRequest` (item 1) and consume a terminal `RunOutput` **or** a `StepRequirement` (`A/workflow/types.py:810`) when the run suspended. `HumanReview` (`A/workflow/types.py:64-105`) is evaluated by the workflow engine, never by the agent loop.

**9. Session identity.** One key type must be shared: OpenClaw's `ContextEngineSessionTarget{agentId, sessionId, sessionKey, storePath, threadId}` (`B/src/context-engine/types.ts:157-168`). Agno's `AgentSession.session_id` / `agent_id` / `user_id` / `workflow_id` (`A/session/agent.py:19-29`) must be derived from it, not maintained in parallel.
