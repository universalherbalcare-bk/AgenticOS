## Verdict

**MCP — SPLIT, but OpenClaw wins the merged platform on breadth; Agno wins the server.** Agno owns the only production-grade MCP *server*: `libs/agno/agno/os/mcp.py` (2963 lines) mounts a FastMCP Streamable-HTTP app at `/mcp` (`mcp_app = mcp.http_app(**http_app_kwargs)`, mcp.py:2909, with `stateless_http` opt-in at :2887), and `libs/agno/agno/os/mcp_auth_builtin.py` (1118 lines) makes the deployment its **own OAuth 2.1 authorization server** — `/authorize`, `/token`, `/register`, `/revoke`, PKCE S256, public-clients-only DCR, SHA-256 hash-at-rest for codes and refresh tokens, refresh rotation with family-based reuse detection (RFC 9700), and a login+consent page gated on a deployer secret. `mcp_results.py` is a real result serializer that emits typed MCP `ImageContent`/`AudioContent`/`EmbeddedResource`/`ResourceLink` blocks and trims run transcripts before they hit the caller's context window. OpenClaw's server side is thinner — a stdio server (`src/mcp/tools-stdio-server.ts`, 77 lines) plus a **127.0.0.1 bearer-auth loopback** JSON-RPC endpoint (`src/gateway/mcp-http.ts:1-3`: "Exposes Gateway-scoped tools to local MCP clients over bearer-auth loopback") — no OAuth AS, no remote server. But OpenClaw's **client** is decisively richer: all three transports with per-server config (`src/config/types.mcp.ts:22-80` — `transport: "stdio" | "sse" | "streamable-http"`, `sslVerify`, `clientCert`/`clientKey` mTLS, `toolFilter.include/exclude`, `connectionTimeoutMs`, `requestTimeoutMs`, `supportsParallelToolCalls`), a full OAuth *client* with per-requester vs shared credential identity (`src/agents/mcp-oauth.ts`, 543 lines + `mcp-oauth-store.ts` 452 + `mcp-oauth-provider.ts` 199, state-leased at `withOpenClawStateLease({scope:"core:mcp-oauth"})`), resource listing (`src/agents/agent-bundle-mcp-runtime.ts:659` `session.client.listResources(...)`), and MCP Apps / UI resources (`src/agents/mcp-ui-resource.ts`, `MCP_APP_RESOURCE_MIME_TYPE = "text/html;profile=mcp-app"` with CSP sandboxing). Agno's client (`libs/agno/agno/tools/mcp/mcp.py`, 977 lines) does stdio/SSE/streamable-http via fastmcp transports (mcp.py:179-235) but I found **no** `list_resources`/`list_prompts`/sampling/elicitation calls in it. **Winner: OpenClaw for the client, Agno for the server — the merge must take both halves.**

**Scheduling — Agno wins on durability and distribution; OpenClaw wins on scheduling semantics.** Agno's scheduler is genuinely distributed: `db/postgres/postgres.py:7085-7119` claims a due schedule with an atomic `UPDATE ... RETURNING` over a `SELECT ... FOR UPDATE SKIP LOCKED` subquery, stamping `locked_by=worker_id, locked_at=now`, with stale-lock reclaim via `locked_at <= now - lock_grace_seconds`; the same contract is implemented for SQLite, async-SQLite, Mongo, async-Mongo, async-Postgres (`db/base.py:1841`, `:3216`). `scheduler/poller.py` runs N workers with `worker_id`/`max_concurrent`; `scheduler/executor.py:173-250` implements `max_attempts = (max_retries or 0) + 1` with `retry_delay_seconds` backoff and always releases the lock in a `finally`. Alongside it, `os/job_queue.py` (2446 lines) is a real durable work queue — `claim_job`/`heartbeat_jobs`/`complete_job`/`retry_or_fail_job`/`sweep_exhausted_jobs`/`acquire_sweep`/`settle_swept_job` (`job_queue/store.py:54-228`), idempotency keys (`normalize_idempotency_key`, os/job_queue.py:173), crash recovery via sweeps, and optional Redis coordination for cross-replica cancel + event stream (`job_queue/config.py`). OpenClaw's cron is **single-node**: SQLite-backed (`src/cron/store.ts`, "backed entirely by shared SQLite state"), timer-driven, with no lease/claim/worker-id anywhere — my grep for `lease|distributed|multi-node|singleton` across `src/cron/service.ts`, `runtime-authority.ts`, `local-service.ts` returned **nothing**. Its schedule *semantics* are far better, though: five schedule kinds (`src/cron/types.ts:28-53` — `at`, `every`, `cron`, `on-exit`, `stream`), Croner with real IANA timezone + DST-transition handling (`src/cron/schedule.ts:52` `hasNearbyCronTimezoneTransition`), deterministic top-of-hour jitter (`src/cron/stagger.ts`, `DEFAULT_TOP_OF_HOUR_STAGGER_MS = 5 * 60 * 1000`), restart catch-up, a heartbeat monitor, delivery plans/previews with failure notification, and a genuinely careful retry classifier (`src/cron/retry-hint.ts`: `rate_limit`/`overloaded`/`network`/`timeout`/`server_error` with regexes written specifically to *avoid* misreading "context limit 512 exceeded" as a 5xx). **Winner: Agno** — durability and multi-replica correctness are the non-negotiable half.

**Observability — OpenClaw wins, decisively.** OpenClaw ships a first-class OTel plugin (`extensions/diagnostics-otel/`) exporting **traces + metrics + logs** over OTLP, with a composite propagator supporting W3C tracecontext, W3C baggage, B3 and Jaeger (`src/service-propagation.ts:14-20`), an owned `AsyncLocalStorageContextManager`, exporter health checks (`service-exporter-health.ts`), and correct **GenAI semantic conventions** — `gen_ai.client.token.usage` and `gen_ai.client.operation.duration` (`src/service-metrics.ts:64,71`) alongside ~40 `openclaw.*` instruments (gateway RPC latency/queue-wait/admission, event-loop delay, run duration, queue depth, session-stuck age). A separate Prometheus exporter (`extensions/diagnostics-prometheus/src/service.ts`, 1148 lines) publishes ~40 `openclaw_*_total`/`_seconds` series with a `openclaw_prometheus_series_dropped_total` cardinality guard. Structured logging is a subsystem in its own right (`src/logging/`, ~120 files: leveled logger, file transport with size cap, JSON console lines, `redact.ts` + `redact-patterns.ts` + `secret-redaction-registry.ts`, `diagnostic-support-bundle.ts`/`diagnostic-support-export.ts` with `diagnostic-support-log-redaction.ts`). And there is a real **audit ledger**: `src/audit/audit-event-store.ts` — SQLite/Kysely, schema-versioned (`AUDIT_EVENT_SCHEMA_VERSION`), cursor-paged, with **pseudonymized identities** (`audit-identity.ts`: `loadOrCreateAuditIdentityKey`, `pseudonymizeAuditIdentity`) and execution-owner lifecycle binding receipts. Agno has one narrow slice: `agno/tracing/` (571 lines total) uses `openinference-instrumentation-agno` + a `DatabaseSpanExporter` that writes spans into the Agno DB (`tracing/exporter.py:19`) — no OTLP export, no metrics pipeline, no log pipeline, no propagators. `agno/metrics.py` (833 lines) is **token/cost accounting dataclasses**, not a metrics system; `agno/debug.py` is 18 lines that flip the log level. I found **no** audit-event store in `agno/os/` (grep for `audit` hit only `routers/approvals/router.py`, `middleware/jwt.py`, `event_streams/redis.py`). **Winner: OpenClaw.**

**Eval/QA — Agno wins for measuring agent output; OpenClaw wins for measuring the product.** These two are not the same system and the comparison is often made wrongly. Agno's `agno/eval/` (~3300 lines) is a **programmable, DB-persisted evaluation framework** a user runs against their own agents: `accuracy.py` (886 lines, LLM-judge scoring 1-10 with reasons, `AccuracyAgentResponse`), `performance.py` (785, latency/memory runs), `reliability.py` (426, tool-call assertions), `agent_as_judge.py` (920), `suite.py` (1012), persisted through `agno.db.schemas.evals.EvalType`. `agno/scorer/` adds composable scorers — `CodeScorer`, `JudgeScorer`, `ToolCallScorer` over a `Score`/`Scorer` base (`scorer/__init__.py`). OpenClaw's `qa/` + `.agents/skills/{auto-qa,autoreview,claw-score}` are a different animal: a YAML **scenario pack** (`qa/scenarios/index.yaml` + ~20 theme dirs) where each scenario declares `coverage.primary` IDs and an executable `execution.kind: vitest|playwright|script` path (e.g. `qa/scenarios/observability/cached-health-snapshot-boundaries.yaml` → `test/e2e/qa-lab/runtime/cached-health-snapshot-boundaries.ts`), driven by the `qa-lab` extension (`extensions/qa-lab/src/`, incl. `suite.ts`, `cli.ts`, `agentic-parity-report.ts`, and an actual multi-model LLM-judge harness in `character-eval.ts`), scored into `qa/maturity-scores.yaml` (50 surfaces, 280 category scores, quality/completeness rollups) against a hand-edited `taxonomy.yaml`. `auto-qa`/`autoreview`/`claw-score` are **agent skills** — markdown workflows for a coding agent, not runtime libraries. Only one of these belongs to a *platform*: an eval API users call on their own agents. **Winner: Agno** — but its win is narrow and OpenClaw's coverage-ID/maturity machinery has no Agno counterpart at all.

**Configuration — OpenClaw wins, not close.** Agno's config is two pydantic models: `os/settings.py` is **54 lines** of `BaseSettings` (env vars: `os_security_key`, `authorization_enabled`, CORS list) and `os/config.py` (534 lines) is `AgentOSConfig` — a typed, in-code Python object with per-domain sub-configs. There is no file format, no layering, no hot reload: I grepped `os/app.py` for `yaml.safe_load|from_yaml|config_file` and found **nothing**. OpenClaw has a whole config subsystem: `src/config/` holds **253 non-test modules**, with a JSON5 file format; `$include` layering with depth/size/path-traversal limits (`src/config/includes.ts`: `MAX_INCLUDE_DEPTH = 10`, `MAX_INCLUDE_FILE_BYTES = 2MB`, `MAX_INCLUDE_PATH_LENGTH = 4096`, `isPathInside` guard); `${VAR}` env substitution that **fails closed** on a missing var (`src/config/env-substitution.ts`: `MissingEnvVarError`) with `$${}` escaping; a generated + validated JSON Schema with UI hints, tiering and sensitive-field marking (`src/config/schema.ts`, `applySensitiveHints`, `applyConfigTierHints`, checked in CI by `check:base-config-schema`); secret refs kept out of config entirely (`src/secrets/ref-contract.ts`, `types.secrets.ts`, and MCP OAuth tokens explicitly "stored in OpenClaw state, not in config" — `types.mcp.ts:47`); config journaling and backup rotation (`config-journal-snapshot.ts`, `backup-rotation.ts`); and genuine **hot reload** with a reload plan, debounce, and native-watcher→polling degradation (`src/gateway/config-reload.ts:1231` "config watcher native retries exhausted; degrading to polling mode"). **Winner: OpenClaw.**

**Build & CI — OpenClaw wins for tooling depth; Agno's Python toolchain is fine and should simply be kept for Python.** Agno: 7 GitHub workflows (`test.yml`, `pr-lint.yml`, `release.yml`, `performance.yml`, …); `ruff==0.15.20` + `mypy==2.1.0` + `pytest==9.1.1` pinned in `libs/agno/pyproject.toml [dev]`; `scripts/validate.sh` runs ruff+mypy across `agno`, `agnoctl` and the cookbook and exits non-zero — a clean, gateable local check. Deployment tooling exists as `libs/agno_infra` (AWS/Docker resource management, `ag`/`agno` CLI) and `libs/agnoctl` (project scaffolding, `agno create`/`agno up`, nine starters). OpenClaw: **101 workflows** in `.github/workflows/` including 4 CodeQL lanes, `dependency-audit`, `dependency-guard`, `install-smoke`, `docker-release`, `full-release-validation`, `ci-test-timings-refit`; `pnpm@12.3.4` workspace; `oxlint`/`oxfmt` for lint/format; `tsdown` for bundling (`tsdown.config.ts` with per-group configs, plugin-SDK entry generation, declaration-boundary hooks); `vitest` with a project matrix (`vitest.config.ts` → `test/vitest/vitest.config.ts`, pool + worker scheduling resolvers); `tsgo` for typechecking; plus dozens of custom **architecture ratchets** (`check:import-cycles`, `check:madge-import-cycles`, `check:max-lines-ratchet`, `check:assertion-safety`, `check:env-var-count`, `check:deprecated-api-usage`, `check:wrapper-shadowing`, `check:database-first-legacy-stores`), a digest-pinned multi-stage `Dockerfile` (`node:24-bookworm@sha256:…`), `docker-compose.yml`, `fly.toml` + `deploy/fly.private.toml`, `render.yaml`. **Winner: OpenClaw** — but this is a per-language verdict, not a replacement of Python tooling.

## Salvage list

From **OpenClaw** (loser on MCP-server, scheduling durability, agent-eval):
- `src/agents/mcp-oauth.ts`, `mcp-oauth-store.ts`, `mcp-oauth-provider.ts`, `mcp-oauth-identity.ts`, `mcp-auth-profile.ts` — the only OAuth *client* in the merge; Agno has nothing for connecting to third-party OAuth MCP servers.
- `src/config/types.mcp.ts` — the per-server config surface (mTLS, `toolFilter`, timeouts, `supportsParallelToolCalls`) that Agno's `MCPTools` constructor cannot express.
- `src/agents/mcp-ui-resource.ts` + `src/gateway/mcp-app-sandbox-http.ts` — MCP Apps / UI resources; no Agno equivalent exists.
- `src/agents/mcp-json-schema-validator.ts` — validates tool arg schemas before dispatch; Agno's `_schema_validator` (os/mcp.py:524) covers only its own server.
- `src/cron/schedule.ts` + `stagger.ts` — Croner tz/DST correctness and deterministic top-of-hour jitter; Agno's `scheduler/cron.py` is 94 lines and does neither.
- `src/cron/types.ts` schedule kinds `on-exit` and `stream` — trigger classes Agno's `Schedule` has no representation for.
- `src/cron/retry-hint.ts` — the transient-error classifier; Agno retries blindly on any exception.
- `src/cron/heartbeat-monitor.ts` + `failure-notification-text.ts` + `delivery-plan.ts` — nothing in Agno tells an operator a schedule silently stopped firing.
- `extensions/qa-lab/src/character-eval.ts` + `suite.ts` + `cli.ts` — the executable scenario runner; the natural host for Agno's scorers.
- `qa/scenarios/**` + `taxonomy.yaml` + `qa/maturity-scores.yaml` + `.agents/skills/claw-score` — coverage-ID→feature→surface traceability; Agno has no readiness scorecard at all.

From **Agno** (loser on observability, config, build/CI):
- `libs/agno/agno/os/mcp_auth_builtin.py` + `os/mcp_auth.py` + the `BaseDb.*_mcp_oauth_*` store contract — the merged product's *only* path to being an OAuth-protected remote MCP server that claude.ai/ChatGPT can connect to.
- `libs/agno/agno/os/mcp_results.py` — typed MCP content-block serialization and transcript trimming; OpenClaw's loopback server returns tool results without this shaping.
- `libs/agno/agno/os/mcp.py` built-in tool-tagging (`MCP_BUILTIN_TAGS`, `_BUILTIN_TOOL_NAMES`, `_EXPOSED_COMPONENT_ANNOTATIONS`) — declared `readOnlyHint`/`destructiveHint`/`openWorldHint` on every tool; OpenClaw's served tools do not declare these.
- `libs/agno/agno/db/*/…claim_due_schedule/release_schedule` — the `SKIP LOCKED` lease that makes scheduling multi-replica-safe. This is the single most important salvage in the whole document.

## Bridge requirements

These must be **one** service in the merged repo, not two.

1. **One trace context.** The OTel `AsyncLocalStorageContextManager` + composite propagator in `extensions/diagnostics-otel/src/service-propagation.ts` becomes the single context authority. The Python side stops installing its own `TracerProvider` in `tracing/setup.py`; instead `setup_tracing` accepts an externally configured provider and the Python process inherits `traceparent` from inbound HTTP headers (W3C is already in `DEFAULT_PROPAGATORS`). Concretely: every cross-process hop — Gateway→AgentOS HTTP call, `scheduler/executor.py:_call_endpoint`, `os/mcp.py:_detached_trace_context` (:1047) — must inject/extract `traceparent`. Today Agno spans and OpenClaw spans share no trace id, so a scheduled run cannot be followed end to end.

2. **One metrics registry.** `agno/metrics.py` dataclasses stay as the *accounting model* but must emit into the OTel meter, not just into `RunMetrics`. Map `input_tokens`/`output_tokens`/`cache_read_tokens` onto the existing `gen_ai.client.token.usage` histogram (`service-metrics.ts:64`) with `gen_ai.*` attributes, so Prometheus (`diagnostics-prometheus/src/service.ts`) exposes one token series, not an Agno one and an OpenClaw one.

3. **One config file and schema.** OpenClaw's JSON5 + `$include` + `${VAR}` + generated JSON Schema (`src/config/schema.ts`) is the format. Agno's `AgentOSConfig`/`MCPConfig`/`AuthorizationConfig` pydantic models become a **generated** namespace inside it (`agentos.*`), produced by exporting pydantic JSON Schema and merging via `mergeObjectSchema` (schema.ts:38). The Python process reads the resolved config over the existing `config.get` path rather than re-parsing files, and `check:base-config-schema` gains a Python lane so a drifted pydantic model fails CI. Secrets stay in `src/secrets/ref-contract.ts` refs and OpenClaw state — never in the config file, and never in `AgnoAPISettings.os_security_key` as a raw env value.

4. **One job queue and one scheduler.** Merge Agno's lease semantics into OpenClaw's scheduler rather than running both: add `locked_by`/`locked_at`/`next_run_at` columns and the `claim_due_schedule` contract (`db/base.py:1841`) to the SQLite cron store (`src/cron/store/schema.ts`), so `src/cron/service.ts` claims through a lease instead of assuming process singleton — that is what unblocks multi-node OpenClaw. Then retire the standalone Agno poller (`scheduler/poller.py`) and have Agno schedules submit onto the unified queue. Postgres remains the backend for multi-replica deployments (the `SKIP LOCKED` path already exists at postgres.py:7107); SQLite stays the single-node default.

5. **One audit and run-history ledger.** `src/audit/audit-event-store.ts` (schema-versioned, cursor-paged, pseudonymized identities) is the system of record. Agno's `schedule_runs` and eval-run rows write **into** it via a bridge writer rather than owning parallel tables, so `src/cron/task-run-history.ts` can render a scheduled Agno agent run and a scheduled OpenClaw cron job in the same list with the same ownership bindings.

6. **One MCP identity plane.** The merged product is simultaneously an MCP server (Agno's OAuth AS) and an MCP client (OpenClaw's OAuth client). These must share one token store and one principal model: `mcp_auth.py`'s identity bridge (`request.state.user_id`/`scopes`/`authorization_enabled`) and OpenClaw's `McpOAuthIdentity` (`shared` vs `per-requester`, `src/agents/mcp-oauth-identity.ts`) are today two unrelated notions of "who is calling". Pick OpenClaw's per-requester identity as the outward model, Agno's scoped principal as the inward one, and define the mapping explicitly — otherwise a per-requester downstream token will be exercised under a shared inbound principal, which is a real privilege-crossing bug, not a cosmetic duplication.

7. **One tool-annotation contract.** Agno declares all three of `readOnlyHint`/`destructiveHint`/`openWorldHint` on every served tool (`os/mcp.py:97-115`); OpenClaw's `createToolsMcpServer` does not. Apply Agno's rule to every tool served from either side, and enforce it with a ratchet in the `check:` family — a hint the server declines to state is one a client answers on its behalf.
